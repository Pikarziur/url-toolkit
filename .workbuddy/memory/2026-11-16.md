## 架构改动：禁拍静态库改为本地打包，弃用外部 CDN
- 背景：用户更新本地 ban/*.json 并传 GitHub 后，线上仍显示旧条数（236/1305/186）。根因：网站数据源是 `Pikarziur/Data@main/BanShop/` 的 jsDelivr CDN，与本地 ban/ 无关；且「更新于」是硬编码常量，非真实指标。
- 改动（src/App.vue）：
  1. 删 `BAN_URLS`（jsDelivr 三个地址），改为顶部 `import anhengData/errorData/longData from '../ban/*.json'` —— Vite 静态打包进 bundle，随构建发布。
  2. `anhengList/errorList/longList` 用打包数据直接 `ref()` 初始化，秒开、免网络、无缓存滞后。
  3. 删除原 CDN 加载链路（BAN_CACHE_KEY/loadBanCache/saveBanCache/applyBanData/fetchBanNetworkData），`loadBanData()` 现只拉自定义库（KV）+ 单独的 custom 缓存 key `ban-custom-v1`。
  4. banLoading 恒 false，加载文案改「正在加载自定义禁拍库…」。
- 验证：`npm run build` 通过（14 模块，JS 106→148KB）；bundle 含三库首尾店名，无 `Pikarziur/Data` 残留。
- 效果：以后只需改本地 ban/*.json → 重新 build + 部署即生效，不再依赖外部仓库/CDN 缓存。Custom 自定义库仍走 KV 持久化不变。
- ⚠️ BAN_DATA_UPDATED 仍是手填常量，每次更新数据需同步改日期（用户已知）。
